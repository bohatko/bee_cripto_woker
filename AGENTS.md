    ├── Dockerfile             # Multi-stage production build для Railway
    ├── src/
    │   ├── index.ts           # Точка входа воркера

## 4. Торговая Стратегия и Критические Константы

Стратегия — **Multi-Pair Market-Neutral Alpha Basket** (рыночно-нейтральный спред с $\beta = 0$):

1. **Состав корзины (4 структурные пары)**:
   * Нога 1: `LONG ZEC` + `SHORT AVAX` (Пара цикла: приватный прорыв vs затухание L1).
   * Нога 2: `LONG ENA` + `SHORT SUI` (DeFi доходность vs инфляционный альткоин).
   * Нога 3: `LONG SOL` + `SHORT ADA` (Лидер объема vs стагнирующий мейджор).
   * Нога 4: `LONG BNB` + `SHORT ETH` (Биржевая утилита vs слабый L1 спред).
2. **Правило входа**:
   * Отношение цен $\text{Ratio} = \text{Price}_{\text{Long}} / \text{Price}_{\text{Short}}$.
   * Вход **ТОЛЬКО** когда $\text{Ratio} > \text{EMA}_{10}$ (на 4-часовом таймфрейме).
3. **Распределение капитала**:
   * Депозит делится на 4 равных слота: **25% свободной маржи на пару**.
   * Рабочее эффективное плечо: **7.0x**.
   * Объем делится поровну между лонгом и шортом: $\text{Volume}_{\text{leg}} = (\text{Margin} \times 7) / 2$.
4. **Условия выхода**:
   * **Take-Profit (TP)**: фиксированный **+5.0%** на суммарную связку.
   * **Stop-Loss (SL)**: фиксированный **-1.5%** на связку.
   * **Trend-Flip**: 4-часовая свеча закрылась ниже $\text{EMA}_{10}$ — немедленное закрытие.
   * **Panic Close**: пользователь нажал экстренную кнопку в интерфейсе.

## 5. Правила Безопасности для Агентов (НЕ НАРУШАТЬ)

1. **Никаких ключей с правами на вывод**:
   * При валидации API-ключей биржа опрашивается на флаг `withdraw`. Если он активен (`true`), сохранение ключа **строго блокируется**.
2. **Шифрование ключей в БД**:
   * API-ключи, секреты и пароли хранятся в таблице `exchange_accounts` **исключительно зашифрованными алгоритмом AES-256-GCM**.
   * Никогда не сохраняйте открытые ключи в БД.
   * Расшифровка происходит исключительно в оперативной памяти воркера перед запросом к бирже.
3. **Статический IP Railway (`54.198.120.45`)**:
   * Всегда напоминать пользователю указывать данный IP в белом списке на бирже.
4. **Все критические действия — через модалки подтверждения**:
   * Старт/остановка бота, удаление ключей, выход из системы — через `ConfirmModal`.
   * Экстренная ликвидация позиций — через `PanicCloseModal` с обязательным вводом слова `CLOSE`.
5. **Политика неоплаты инвойсов (Вариант А — Безопасный)**:
   * При просрочке платежа (`is_frozen = true`) воркер **запрещает открывать новые связки**, но **продолжает сопровождать уже открытые позиции** до срабатывания TP (+5%) или SL (-1.5%). Никакого принудительного аварийного сброса позиций при неоплате!

## 6. Правила Разработки и Кодинга

* **Языковые правила**:
  * Тексты интерфейса, кнопки, логи, подсказки в коде — **ТОЛЬКО НА АНГЛИЙСКОМ** (English).
  * Ответы пользователю в диалоге — **ТОЛЬКО НА РУССКОМ** (Русский язык).
* **Стилизация UI**:
  * Использовать темную neo-fintech тему на Tailwind CSS.
  * Основной цвет бренда: Медово-янтарный (`#F59E0B`, класс `text-honey-400`, `bg-honey-500`).
  * Для прибыли: Изумрудный (`text-emerald-400`).
  * Для убытков и стопов: Рубиновый (`text-rose-400`).
  * Для цен и финансовых данных: использовать моноширинный шрифт (`font-mono`).
* **Работа с базой данных**:
  * Не удалять таблицы и не сбрасывать данные без явного указания.
  * Помнить, что на всех таблицах включен RLS. Серверные скрипты воркера должны использовать `SUPABASE_SERVICE_ROLE_KEY` или сервисный доступ, а фронтенд — клиентский `SUPABASE_ANON_KEY`.

## 7. Команды для Локального Запуска и Сборки

```bash
# 1. Запуск воркера (Торгового ядра)
cd worker
npm run dev      # Запуск с автоперезагрузкой через tsx
npm run build    # Компиляция TypeScript в dist/
npm start        # Запуск скомпилированного демона

# 2. Запуск фронтенда (Next.js 15)
cd web
npm run dev      # Запуск дев-сервера на http://localhost:3000
npm run build    # Проверка типов и продакшн-сборка
npm start        # Запуск собранного Next.js

# 3. Деплой воркера на Railway
railway up       # Деплой из папки worker или корня репозитория
```
