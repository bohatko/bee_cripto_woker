# 07. Спецификация Сигнального Модуля: Dip-Buy (XRP / ETH / BTC)

## 1. Обзор и Цели

Модуль **Dip-Buy Signals** интегрирован в единый 24/7 демон воркера на Railway (`worker/`) в качестве независимого торгового ядра сигналов наряду с мультипарной рыночно-нейтральной корзиной (`MarketScanner`).

Поддерживаемые монеты и конфигурации:
1. **XRP Dip-Buy 24h (`xrp_dip_buy_v1`)**:
   - Монета: `XRP/USDT`, `LONG`
   - Вход: Падение цены $\ge 15.0\%$ за последние 24 часа (1440 1-минутных закрытых баров)
   - Плечо: **3.0x Isolated**
   - Take-Profit: **+4.0%**
   - Stop-Loss: **-30.0%**
2. **ETH Dip-Buy 1h (`eth_dip_buy_v1`)**:
   - Монета: `ETH/USDT`, `LONG`
   - Вход: Падение цены $\ge 5.0\%$ за последний 1 час (60 1-минутных закрытых баров)
   - Плечо: **1.75x Isolated**
   - Take-Profit: **+2.0%**
   - Stop-Loss: **-15.0%**
3. **BTC Dip-Buy 7m (`btc_dip_buy_v1`)**:
   - Монета: `BTC/USDT`, `LONG`
   - Вход: Падение цены $\ge 3.0\%$ за последние 7 минут (7 1-минутных закрытых баров)
   - Плечо: **3.0x Isolated**
   - Take-Profit: **+3.0%**
   - Stop-Loss: **-12.0%**

Воркер поднимает сканеры/гарды динамически из `signal_strategies` (`is_enabled=true`), без хардкода списка монет в `index.ts`.

## 2. Архитектура и Разделение Ответственности

1. **`CandleBuffer` (`worker/src/signals/candle-buffer.ts`)**:
   - Кольцевой буфер 1-минутных баров (емкость 2000 свечей).
   - Расчет `rollingMaxHigh(1440, exclusiveOfLast)` — максимум цен High за последние 1440 закрытых баров (не включая формирующийся бар).
   - Расчет `calculateDropPct(currentPrice, rollingMax)`.

2. **`DipBuyScanner` (`worker/src/signals/dip-buy-scanner.ts`)**:
   - Работает через `ccxt.binanceusdm` (публичный коннектор котировок фьючерсов).
   - Предзагрузка истории при старте (1500 1m баров).
   - Тик каждую минуту по границе минуты (+2с задержки для фиксации закрытия бара на бирже).
   - Расчет метрики **Readiness** в процентах: $\text{clamp}((\text{drop} / 15.0) \times 100, 0, 100)$.
   - Запись состояния в `signal_strategies.live_state` (Realtime-источник для UI дашборда).
   - Создание записи в `signal_events` при выполнении условия `drop >= 15.0%`.
   - Защита от старых сигналов при рестарте (сигналы старше 2 минут игнорируются).

3. **`ReadinessAlerter` (`worker/src/signals/readiness-alerter.ts`)**:
   - Отслеживает приближение цены к сигналу (пороги 80%, 90%).
   - Оповещает админов и подписанных пользователей в Telegram.
   - Гистерезис сброса порога: сбрасывается только при падении readiness ниже `порог - 10 п.п.`.
   - Состояние оповещенных порогов сохраняется в `live_state.alerted_thresholds`.

4. **`DipBuyRouter` (`worker/src/signals/dip-buy-router.ts`)**:
   - Отправка алерта `notifySignalFired` подписчикам.
   - Создание **Benchmark Master Paper** позиции в `signal_positions` ($20,000 reference margin, $60,000 notional, проскальзывание 0.05%, комиссия 0.1%).
   - Fan-out исполнение сделок на пользователей с включенным тумблером `user_signal_settings.is_enabled = true`.
   - Проверка баланса futures USDT, расчет маржи: $\text{freeBalance} \times \text{balance\_pct} / 100$.
   - Установка плеча 3.0x и режима Isolated.
   - Размещение рыночного входа (Market Buy), затем выставление нативных биржевых ордеров reduce-only TP (+4%) и SL (-30%).

5. **`DipBuyGuard` (`worker/src/signals/dip-buy-guard.ts`)**:
   - Опрос позиций каждые 15 секунд (`DIP_GUARD_INTERVAL_MS`).
   - Для Master Paper: симуляция закрытия по 1m барам (`low <= sl` -> выход min(open, sl); `high >= tp` -> выход tp; при конфликте приоритет у SL).
   - Для Live-пользователей: проверка фактического размера позиции на бирже (`fetchPositions`). При нулевом контракте — определение причины выхода (TP/SL) по биржевым ордерам, отмена парного ордера, подсчет PnL и закрытие в базе.
   - Fallback-защита: если биржевые TP/SL ордера не были приняты биржей при входе, воркер закрывает позицию по рынку при пересечении цен TP/SL.
   - Обработка `panic_close_requested_at`: немедленная ликвидация по рынку, отмена ордеров, выключение тумблера.

## 3. Таблицы Базы Данных Supabase

- `signal_strategies`: Каталог стратегий сигналов (начальная строка `xrp_dip_buy_v1`). Поля: `config`, `is_enabled`, `live_state`.
- `user_signal_settings`: Настройки пользователя (`user_id`, `strategy_id`, `is_enabled`, `balance_pct`, `alert_readiness_enabled`, `alert_thresholds`, `panic_close_requested_at`).
- `signal_events`: Лог глобальных срабатываний сигналов сканером.
- `signal_positions`: Мастер-позиции (`is_master=true`) и клиентские сделки (`is_master=false`).

## 4. Меры Безопасности и Риск-Менеджмент

1. **One-Way Position Mode**:
   Вход Dip-Buy блокируется, если у пользователя есть открытая позиция парного бота с ногой XRP, во избежание слияния позиций на бирже в режиме One-Way.
2. **Ликвидация vs Stop-Loss**:
   При плече 3.0x Isolated ликвидация биржей наступает при падении цены на ~32-33%. Stop-Loss установлен на -30.0% (потеря ~90% выделенной маржи). В интерфейсе размещено явное предупреждение о рисках.
3. **Безопасная заморозка (Safe Freeze)**:
   При просрочке подписки воркер запрещает новые входы по сигналам, но продолжает корректно сопровождать уже открытые позиции до выхода.
