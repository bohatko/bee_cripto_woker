# ТЕХНИЧЕСКОЕ ЗАДАНИЕ (ТЗ)
## Проект: Bee Crypto Worker — SaaS Платформа Рыночно-Нейтрального Алготрейдинга

---

## 1. Введение и концепция продукта

### 1.1. Описание
**Bee Crypto Worker** — это финтех SaaS-платформа автоматизированной торговли на криптовалютных фьючерсах по рыночно-нейтральной парной стратегии (Market-Neutral Pair Trading / Statistical Arbitrage).

Платформа позволяет пользователю любого уровня подготовки:
1. Зарегистрироваться в сервисе за 1 минуту.
2. Подключить свои API-ключи от бирж (**Binance, OKX, Bybit**).
3. Активировать торгового робота в один клик.
4. Получать системную прибыль на автопилоте без направленного риска на Биткоин (капитал захеджирован в синтетических спредах).

### 1.2. Бизнес-модель (Монетизация)
* **Бесплатный триал**: 7 календарных дней с момента регистрации (полный функционал без ограничений).
* **Базовая подписка**: **$20 в неделю** (фиксированная абонентская плата за поддержание инфраструктуры).
* **Success Fee (Плата за результат)**: **10% от чистой прибыли** пользователя за отчетную неделю.
* **Принцип High-Water Mark (HWM)**: 10% берутся только с абсолютной новой прибыли. Если баланс проседал, комиссия за прибыль не начисляется, пока счет не обновит исторический пик доходности.
* **Оплата**: Полуручной режим на кошелек биржи по QR-коду / адресу сети (USDT TRC-20 / BEP-20). Пользователь прикрепляет хеш транзакции (TxID) или скриншот, администратор подтверждает в 1 клик в панели управления.
* **Политика неоплаты (Вариант А — Безопасный)**: Если инвойс не оплачен по истечении 48-часового льготного периода (Grace Period), **замораживаются ТОЛЬКО новые входы в позиции**. Все текущие открытые позиции продолжают сопровождаться торговым движком в штатном режиме до тейк-профита или стоп-лосса. Никаких принудительных ликвидаций депозита клиента.

### 2.1. Стек Frontend & Web App
* **Фреймворк**: Next.js 15 (App Router, React 19, TypeScript).
* **Стилизация**: Tailwind CSS 3.4+ с кастомной темной неоновой темой (стиль Raydium / Linear / OKX Web3).
* **Компоненты**: `shadcn/ui` (Radix UI primitives).
* **Графика и иконки**: `lucide-react`, `framer-motion` (плавные анимации интерфейса).
* **Графики**: Lightweight Charts (TradingView) / Recharts для визуализации кривой PnL и спредов.
* **Хостинг фронтенда**: Vercel или Railway.

### 2.2. Стек Базы Данных и Авторизации (Supabase)
* **СУБД**: PostgreSQL 15+ в Supabase.
* **Аутентификация**: Supabase Auth (Email + Пароль, Google OAuth, опционально Web3 Wallet).
* **Безопасность данных**: Row-Level Security (RLS) — изоляция данных на уровне строк БД. Пользователь А физически не может прочитать ключи или историю пользователя Б.
* **Реактивность**: Supabase Realtime — мгновенный пуш балансов, статусов позиций и системных уведомлений в браузер без опрашивания сервера (polling).

### 2.3. Стек Торгового Ядра (Railway Worker Engine)
* **Среда**: Постоянный 24/7 фоновый сервис (Daemon) на платформе **Railway**.
* **Статический исходящий IP (Static Egress IP)**: обязательное требование для предоставления пользователям фиксированного IP-адреса сервиса для внесения в IP Whitelist на биржах.
* **Язык**: Node.js 22 LTS / TypeScript.
* **Библиотека взаимодействия с биржами**: `ccxt` / `ccxt.pro` (унифицированный слой для Binance USD-M Futures, OKX USDT SWAP, Bybit Linear Futures).
* **Шифрование**: Модуль `crypto` Node.js (алгоритм AES-256-GCM). Мастер-ключ шифрования находится строго в переменных окружения сервера Railway и никогда не сохраняется в БД.

## 3. Функциональные модули платформы

### 3.1. Публичный Лендинг (Landing Page)
* **Hero-секция**:
  * Заголовок: *"Рыночно-нейтральный алготрейдинг институционального уровня прямо на вашем биржевом аккаунте"*.
  * Подзаголовок: *"+6,738% исторической доходности за 6 месяцев при максимальной просадке всего 8.7%. Торговля без риска ликвидаций от дампов Биткоина"*.
  * Кнопки CTA: «Попробовать 7 дней бесплатно», «Смотреть live-статистику».
  * Интерактивный виджет живого статуса 4 торговых пар (актуальные спреды и текущий тренд).
* **Интерактивный калькулятор доходности**:
  * Ползунок депозита пользователя (от $500 до $100,000).
  * Динамический расчет расчетной доходности за 1 неделю, 1 месяц, 6 месяцев на основе бэктестов корзины.
* **Блок сравнения**:
  * Таблица «Обычный трейдер / Сигналы» против «Bee Crypto Worker» (отсутствие ночного стресса, ликвидаций, человеческого фактора).
* **Прозрачная статистика**:
  * Суммарный объем под управлением (AUM).
  * Общий винрейт стратегии (62.3%).
  * Количество активных инстансов.
* **Тарифы**:
  * Понятная карточка: «7 дней триал» -> «$20/нед + 10% от чистой прибыли». Пояснение принципа High-Water Mark.
* **FAQ и футер**:
  * Ответы на вопросы о безопасности ключей (запрет вывода, IP-whitelist, шифрование).

### 3.2. Личный кабинет (User Dashboard)
* **Шапка кабинета**:
  * Баланс пользователя (подтягивается с биржи через API).
  * Индикатор здоровья бота (Health Ping): пульсирующий зеленый бейдж `Bot Running / OKX Connected` или желтый `Paused / Pending Invoice`.
  * Дни триала / Статус подписки.
* **Блок быстрого управления (Quick Actions)**:
  * Кнопка `Запустить бота` / `Остановить бота` (всегда открывает модалку подтверждения).
  * Кнопка `Экстренное закрытие позиций (Panic Close All)` (закрывает все ноги связок по рынку с двойным подтверждением).
* **Виджет активных позиций (Live Positions)**:
  * Список открытых парных связок (`ZEC/AVAX`, `ENA/SUI` и т.д.).
  * Для каждой связки отображается:
    * Нога Лонг: монета, цена входа, текущая цена, PnL ($ и %).
    * Нога Шорт: монета, цена входа, текущая цена, PnL ($ и %).
    * Суммарный чистый PnL связки (Net PnL).
    * Расстояние до TP (+5%) и SL (-1.5%).
* **История сделок (Trade History)**:
  * Таблица закрытых раундов с фильтрами по дате, паре и бирже.
  * Экспорт в CSV / Excel.
* **Аналитика PnL**:
  * График прироста депозита (Equity Curve) пользователя день ко дню.

### 3.3. Раздел настроек биржи (API Keys Management)
* Выбор активной биржи: **Binance**, **OKX**, **Bybit**.
* Поля ввода: `API Key`, `API Secret`, для OKX также `Passphrase`.
* **Инструкция со скриншотами**: пошаговое руководство, как создать ключи в личном кабинете каждой биржи.
* **Блок безопасности IP Whitelist**: плашка со статическим IP-адресом воркера и кнопкой «Копировать IP».
* **Автоматическая валидация при сохранении**:
  1. Бэкенд проверяет валидность ключей через `ccxt.fetchBalance()`.
  2. Проверяет права: если включен вывод средств (`withdraw: true`), система **отказывает в сохранении** и требует перевыпустить ключ.
  3. Проверяет доступ к торговле бессрочными деривативами (Futures / Swap).

### 3.4. Модальные окна подтверждения (Confirmation Modals)
Каждое из следующих действий **обязано** вызывать модальное окно с описанием последствий и кнопками «Отмена» / «Подтвердить»:
1. **Запуск бота**: предупреждение о начале автоматического выставления ордеров в соответствии с доступной маржой.
2. **Остановка бота**: предупреждение о том, что новые сделки открываться не будут, а открытые продолжат удерживаться (или предложение закрыть их).
3. **Удаление API-ключей**: предупреждение об обрыве связи с биржей.
4. **Panic Close (Экстренное закрытие всех позиций)**: красная модалка с требованием ввести слово «ЗАКРЫТЬ» или нажать таймер 3 секунды.
5. **Выход из аккаунта (Logout)**.

### 3.5. Модуль Биллинга и Инвойсов
* **Генератор инвойсов**:
  * Каждое воскресенье в 23:59 UTC бэк рассчитывает PnL пользователя за прошедшие 7 дней.
  * Если была чистая прибыль выше предыдущего HWM: формируется инвойс на `$20 + (10% * чистая прибыль)`.
  * Если прибыли не было (или был убыток): инвойс формируется только на фиксированные `$20`.
* **Экран оплаты инвойса**:
  * Сумма к оплате в USDT.
  * Детализация: абонентская плата ($20) + доля от прибыли (расчет по формуле).
  * Выбор сети перевода: USDT TRC-20, USDT BEP-20, USDT TON.
  * Большой четкий **QR-код** кошелька биржи сервиса + текстовый адрес кошелька с кнопкой копирования.
  * Поле ввода: `TxID (Хеш транзакции)` или загрузка чека/скриншота.
  * Кнопка «Я оплатил (Отправить на проверку)».
* **Статусы инвойса**:
  * `issued` (выставлен, идет 48 часов Grace Period).
  * `pending_review` (пользователь отправил TxID, ждет апрува).
  * `paid` (подтвержден, подписка продлена на 7 дней).
  * `frozen` (не оплачен в срок >48ч, новые входы заблокированы).

### 3.6. Панель Администратора (Admin Dashboard)
* Список всех пользователей, балансов, открытых позиций и статусов ботов.
* **Модерация инвойсов**: входящий список оплат с кликабельными ссылками на блокчейн-эксплорер (Tronscan, BscScan) и кнопками `Подтвердить (Approve)` / `Отклонить (Reject)`.
* **Глобальный Health-Monitor**: состояние WebSocket-соединений, латентность API каждой биржи, частота обновления цен.
* **Мастер-рубильник (Emergency Global Stop)**: возможность администратора остановить торговый движок в случае форс-мажора на крипторынке.

## 4. Требования к безопасности и надежности

1. **Безопасность API-ключей**:
   * В базе данных Supabase сохраняются только шифрованные строки `encrypted_api_key`, `encrypted_secret`, `encrypted_passphrase`.
   * Шифрование AES-256-GCM с уникальным вектором инициализации (IV) для каждой записи.
   * Мастер-ключ (`ENCRYPTION_MASTER_KEY`, 32 байта hex) передается только через Railway Environment Variables.
2. **Отказоустойчивость торгового движка**:
   * При падении процесса воркера Railway перезапускает его через `restartPolicy`.
   * При старте движок первым делом опрашивает биржи и сверяет открытые позиции в базе данных с реальными позициями на бирже (Reconciliation Process).
3. **Защита от сбоев биржевых API**:
   * Все вызовы `ccxt` обернуты в Exponential Backoff Retry (повтор через 500ms, 1500ms, 3000ms при таймаутах).
   * Использование WebSocket там, где возможно, для снижения нагрузки на REST API лимиты.
